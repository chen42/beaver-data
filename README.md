# beaver-data

Reproducible, stage-gated data analysis: from raw data intake and forensic exploratory analysis to statistical modeling, cross-engine validation, and LaTeX reporting. It interviews the user before running code, inspects distributions and anomalies before cleaning, executes R or any user-approved statistical and domain toolchain through tracked scripts, and logs every run, branch, and decision.

Part of a four-skill research suite: `beaver-data` (analysis), `weaver-text` (editing support), `honeybee-lit` (general literature reviews), and `wasp-lit` (post-GWAS candidate gene-phenotype literature analysis).

## Why a beaver?

A beaver builds dams in disciplined layers, listens for leaks, and patches weak points before they fail. `beaver-data` treats an analysis the same way: every stage is checked before the next is built on it.

## Reproducibility and standardization

- **Recorded decisions.** Every request, including reanalyses and follow-ups, starts with a requirements interview ("grilling", [Module 02](references/02_grilling_and_intake.md)). Outcomes, comparisons, exclusions, and cleaning rules are confirmed and saved in `plans/` before any code runs.
- **Immutable inputs.** Raw data are never modified; cleaned data are regenerated by tracked scripts.
- **Pinned toolchains.** Each tool's version or container digest, seed, thread count, locale, and numerical options are recorded ([Module 01](references/01_foundations_git_and_bash.md)). R environments use `renv`; other engines use lockfiles.
- **Traceable runs and issue logs.** Each run has a sortable `YYYYMMDD_HHMMSS` run ID. Git tracks scripts, `logs/analysis-index.csv` links runs to outputs, and `issues/` documents edge cases with why each issue needs attention and what happened during the check.
- **Typed plain-text data.** CSV/TSV files with explicit column types prevent `NA` and date auto-conversion errors ([Module 03](references/03_forensics_and_cleaning.md)).
- **Independent validation.** A self-contained, code-isolated brief lets a second engine reproduce key results without reusing the primary code, outputs, or libraries ([Module 05](references/05_validation_and_reports.md)).
- **One project layout and report format.** Every project uses the same flat directories. Reports follow a fixed LaTeX format with machine-readable file-tracking comments.

## What it does

- **Step 1: Confirm Scope and Analysis Questions (`plans/<timestamp>__decisions__<slug>__grilling-summary.md`)**: Inspect workspace files read-only, interview the user briefly across the decision frontier (questions, outcomes, exclusions, assumptions, approved toolchain, visualizations), and save the confirmed decisions before running any code.
- **Step 2: Initialize Project, Git, and Pinned Environment (`renv/`, `logs/analysis-index.csv`)**: Set up the standard project folders, initialize Git and `.gitignore`, and pin the approved statistical environment (`renv` for R or lockfiles/digests for other engines).
- **Step 3: Register Immutable Raw Data (`data/`, `plans/...__source-record.md`, `plans/...__variables.tsv`)**: Record raw data provenance and explicit column types in a variable dictionary without modifying raw files.
- **Step 4: Run Forensic EDA and Deliver Salient Findings Report (`figures/`, `reports/<run_id>__eda__<slug>__summary.md`)**: Run the 30-item forensic EDA checklist ([Module 03](references/03_forensics_and_cleaning.md)), generate multi-angle diagnostic plots, and present the findings report (hardware artifacts, multimodality, assumption risks, subgroup patterns) before proposing any cleaning.
- **Step 5: Approve and Execute Data Cleaning (`plans/...__cleaning__<slug>__approved.md`, `data/`, `results/`)**: Propose cleaning options, obtain user approval, generate deterministic cleaned CSV/TSV files in `data/`, and save row-level exclusion audits in `results/`.
- **Step 6: Formulate Combined Analysis, Toolchain, and Visualization Plan (`plans/<timestamp>__analysis-plan__<slug>__models-and-displays.md`)**: Specify every executable and role, model formulas, contrasts, link functions, assumption checks, sensitivity models, validation engine, and figure/table specifications ([Module 04](references/04_inference_and_displays.md)).
- **Step 7: Run Statistical Models, Diagnostics, and Exploratory Branches (`scripts/`, `figures/`, `results/`, `logs/`)**: Execute noninteractive runs, generate model estimates and diagnostic plot suites (residuals, Q-Q, leverage, BLUPs, `DHARMa`), track exploratory tangents on `explore/<topic>` Git branches, and log every run or retraction in `logs/analysis-index.csv`.
- **Step 8: Validate with an Independent Engine (`validation/<timestamp>__brief__<slug>__<target>.md`, `results/`)**: Reproduce key findings in a second, independent engine from a self-contained brief without sharing primary code or outputs, and compare results side by side ([Module 05](references/05_validation_and_reports.md)).
- **Step 9: Reproduce and Compile Final LaTeX Report (`reports/<timestamp>__final-report__<slug>__report.tex`)**: On user confirmation of completion, verify a clean Git tree, reproduce the accepted workflow in a clean session, and compile the standalone LaTeX/PDF report with file-tracking comments.

## Project workspace

```text
project/
├── data/         # Immutable raw data and generated clean CSV/TSV
├── scripts/      # Tracked analysis scripts
├── plans/        # Grilling summaries, intake records, dictionaries, analysis plans
├── logs/         # Run logs, checkpoints, analysis-index.csv
├── issues/       # Edge cases and resolution records
├── figures/      # Diagnostic and report figures
├── results/      # Plotted data, model summaries, LaTeX table fragments
├── reports/      # EDA summaries and compiled reports (.tex, .pdf)
├── validation/   # Cross-engine briefs, independent implementations, reviews
└── renv/         # R environment, when R is used
```

## Installation

Clone the repository, unchanged, into a skills directory your agent harness scans:

```bash
# Shared cross-harness skills directory (Antigravity, Codex, OpenCode)
git clone https://github.com/chen42/beaver-data.git ~/.agents/skills/beaver-data

# Pi
git clone https://github.com/chen42/beaver-data.git ~/.pi/agent/skills/beaver-data

# Claude Code
git clone https://github.com/chen42/beaver-data.git ~/.claude/skills/beaver-data
```

In Pi, run `/reload` after cloning, or list the path under `"skills"` in `~/.pi/agent/settings.json`.

Requirements: Bash, Git, LaTeX, and the analysis engines approved for each project (R by default).
